# 我的研究情况、失败记录和想法——给 GPT‑6 Pro

我把这个项目目前的全部材料交给你。它来自我和 Codex 围绕事件流（event stream）、复杂事件预测（complex event forecasting）以及 Pattern Markov Chains / Wayeb 做的一系列尝试。附件里有项目结构、代码、协议、结果、失败记录和设计依据。我想让你充分理解这段经历，然后独立思考、研究和推进；具体采用什么方法、怎么组织工作、是否换方向，都由你判断。

最初吸引我的问题是：同一个事件模式、同一个自动机状态，为什么不能因为进度、速度、负载等连续信息不同而得到更细致的未来预测？比如两个任务都在等待完成，但进度一个20%、一个90%。我希望保留原来的业务模式，让额外的传感器、服务器报告或小事件提供预测信息。我关心的是现实流程里未来会发生什么、什么时候发生，以及知道这些之后能做什么。

我们最早实现了保留 Wayeb 识别器的状态增强预测，在 MetroPT 的压缩机加载周期上预测未来30/60/120秒内完成的概率。固定模型、每日重训、两专家组合都经历过失败。一个重要问题是漂移时多个专家会一起给出很低概率，重新加权无法表达现实中很高的完成率；后来加入了快速业务反馈专家，并把同样能力给基线。2022冻结确认中，平均Brier从0.042777降到0.027982，降低34.59%，但数值状态相对16档离散状态的额外改善只有4.24%。延迟或打乱状态后，主要收益会消失。这个任务有效，不代表架构具有足够新颖性，也没有验证跨设备或工业故障预测。

随后我们加入复杂模式、同信息的树模型和神经基线、不同领域和独立年份，研究利用模式结构减少通信。联合损失证书、精确稀疏刷新、独立概率坐标、安全码本四个候选都没有通过主要优势门槛。独立确认的主坐标编码只省0.34%/0.64%的字节，区间包含零。很多看起来合理的解释被推翻：更紧的单步证书不保证闭环少发消息；概率维度降低不保证总字节降低；普通历史策略和同码本基线可以解释所谓新机制的收益。期间也查出了 non-overlap 重置与语言包含关系的语义陷阱、空校准集、投影精度不足和执行开销等问题，具体经过都保留在材料里。

最近一轮转向固定神经源下的多模式概率查询，也发生了多轮失败。Q1只改分配优先级，改善未达原门槛。Q2相对旧基线看似降低约59%误差，但加入更接近的监控状态分组后反而更差，完整输出支持集的必要性没有成立。Q3原来相对IID势基线降低70.60%/53.12%误差，却有高计算成本；后来的一阶Markov-LHS常规基线更强，原来的领先也不能继续成立。Q4的机制对照没有支持它。这里的误差是对一个固定GRU内部概率的数值积分误差，不是现实预测准确性；这与我最初的应用问题已经有明显距离。

Q5保存多个模式的转移闭合占用量，Q6按剩余期限缩小控制空间，仍然保留原始神经历史。它们有一些数学性质和初步好结果，但占用量闭合、平衡抽样、控制变量和有限自动机等价都有既有工作。暂停时Q5每领域只完成42/48个起点，Q6只完成19/48；共同19起点上Q6的用电MSE点估计比Q5一阶方案高约13.22%。完整统计、串行成本和独立确认都没做完。我不认为现有材料已经证明新机制论文成立，也不要求你替Q5/Q6找继续下去的理由。

我现在最重要的想法是：研究应当更多地从真实世界出发。我希望你能去网上寻找真实的应用、例子、问题和代码，尤其是一些开源的、基于事件流的工业应用。制造、设备维护、能源、物流、充电等都可以，领域不必局限在这些。比起一个方便取得的传感器数据集，或人为设计一组A/B/C/D模式，我更想知道现实中谁在处理怎样的事件和流程，现有系统为什么不够好，哪些未来信息确实值得预测，数据是否真的能获得，以及哪里有值得研究的机制问题。我担心之前有一部分工作是在围着自己已有的算法造问题，这也是我希望你独立重审的原因。

这次修改材料时，Codex在网上找到了Fledge的酒庄传感与告警、FledgePOWER的RTE/JEA变电站接入、EVerest充电栈、ThingsBoard机床监测、StreamPipes包装机维护教程和EdgeX/eKuiper工程案例。随后的应用背景附件给出了来源和核查范围。有些是报告过的部署，有些是PoC或模拟教程；还没有从已读页面确认可训练的开放生产日志，也没有证明这些用户都需要概率预测。这些只是目前已知的线索，不是我选定的场景。ThingsBoard最新版本的许可变化、EVerest仓库迁移等也记录了下来。

对我来说，保留某个技术名称、沿用现有架构或继续某个候选都不是目标。你可以质疑我们的前提，推翻以前的解释，重新查文献和代码，沿真实应用发现新的问题；必要时彻底换方向。有工具和执行环境时，也可以在可用权限和资源内自主做能推进问题的工作。你不需要遵循Codex写的研究步骤、路线排序或输出模板，交接材料里的下一步建议只是当时的记录。

我希望最终得到的是有真实价值的问题、可信的设计依据、经得住比较的机制和证据，以及清楚的失败解释。如果暂时找不到足以支撑论文的方向，我也希望知道这个事实。我愿意让你投入充分的思考和研究，尝试、修正、继续推进；无须替已有方案辩护，也无须承诺一定能发论文。请把这些材料作为完整起点，其余由你独立判断。
