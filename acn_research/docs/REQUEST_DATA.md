# A1 用户请求数据核查

## 已核验结果

官方字段文档中的请求字段确实存在于可下载的 ACN 会话导出中，但不是每个会话都有，也不是从连接时刻就已知。本轮官方公开 DEMO_TOKEN 的 office/caltech API 请求超时，未取得实时 API 记录；静态镜像按版本和 Git blob 校验后独立分析。

固定来源为 `yvenn-amara/ev-load-open-data@3b1cb67d1b02f8fea0451c16fbcfaee34449ce46` 下 `1. Input Data/7. ACN Data/`。这是第三方固定导出，不能声称与当前官方服务器逐字节一致。URL、文件大小、Git blob 和 SHA256 见 `reports/request_data_audit.json`。ORNL 另提供仅 26 条用于数据发现的样例，不能当作完整数据集。

| 导出 | 会话数 | 有用户请求 | 多版本请求 | 连接当刻有效请求 | 连接后十分钟有效请求 |
| --- | ---: | ---: | ---: | ---: | ---: |
| office | 1481 | 385 | 44 | 123 | 361 |
| Caltech | 29128 | 14302 | 2220 | 1083 | 14043 |
| JPL | 29724 | 27705 | 4998 | 3524 | 27363 |

这些是导出样本的描述统计，不是整个 ACN 人群的无偏覆盖率。连接后提交和修改请求很常见。JPL 的可用时间查询中还发现一次相同时刻冲突；接口拒绝冲突，不任意选取。

## 与原 128 会话的关联

严格按 sessionID 到录制文件名的规范映射，128 个录制有 117 个匹配，其中 25 个有用户请求。匹配记录的 CSV 首条观测相对元数据连接时刻差为 0–4 秒，中位 3 秒；114 个有断开记录的样本，首次断开相对元数据差为 -6–0 秒，中位 -1 秒。这支持关联，但仍需保留抽取版本与计数器差异。

三个录制的累计电量比元数据少 21.78、3.17、0.25 kWh。逐个排查后，它们全都没有 UNPLUGGED，文件早于元数据断开时刻结束。它们是截断的录制，不能用文件结束作断开或完成；相应观察必须保留删失。这也说明跨来源关联不仅是补字段，还能揭示原 CSV 的覆盖边界。

22 个首告警后恢复会话中，21 个匹配元数据，8 个最终有用户请求，但只有 **5 个在告警时刻已有有效请求**。41 个告警后断开的会话中，4 个在告警时有请求；7 个删失会话中，2 个有。

因此，现有 128 会话无法提供有充分样本量的“真实请求 + 可预测恢复 + 闭环收益”确认。用最终请求回填会把另外三个恢复会话的未来信息提前泄漏；用最终交付电量补缺失请求更会混淆政策结果和需求。

## 因果可用性接口

`request_asof` 只接受 `modifiedAt <= 查询时刻` 的最近有效请求版本；没有请求返回 None。相同时刻冲突拒绝；带时区时间统一 UTC。文档中的 modifiedAt 是用户提交时刻，仍缺少调度器接收时刻。用户声明的能量是服务目标依据，不是独立测得的电池 SoC 或不可观测真实需求。

三个测试验证未来版本不改变过去、无请求不借用最终能量/断开时刻、时间与冲突处理、会话文件名映射。全部通过。

## 对下一阶段的决定

继续跑通作者完整反馈/MPC。恢复取电的信息价值先在显式外生响应模型下检验，包含无拥塞和快反馈的负对照；结果标为仿真，不能称真实场站控制收益。真实 128 会话用于描述性语义和时间尺度检查。独立站点的请求覆盖较高，后续若要训练，应另行冻结对应遥测、按时间分割，并补足动作响应依据。
