# 设计依据与证据边界

## 研究起点

输入是用户的 `Wayeb_Research_Evidence_2026-10-23.zip` 与应用评审；原包散列和选定原文件在 `reference/PROVENANCE.json`。报告的任务建议只是依据，本轮实施来自用户 2026-10-23 的明确授权。

已有 128 个 office 会话说明低电流之后恢复取电确实存在，但没有测量预测优势或控制收益。原始静态 CSV 不含用户请求；官方 API 文档列出 `kWhRequested`、`requestedDeparture`、`modifiedAt`，需要实际检查覆盖、修订与关联，不能用字段文档代替数据。

## 三阶段及防止错误归因

1. **请求数据审计（request-data audit）**：实际获取可访问记录；按 sessionID 关联静态录制，报告缺失率与请求修改时刻。时刻 t 只能读取 `modifiedAt <= t` 的有效请求版本；用户声明不等于电池物理真值。最终交付电量不当作未观测需求。原始记录存忽略目录，Git 只保存汇总、来源和摘要校验。
2. **强基线集成（strong-baseline integration）**：固定 acnportal/adacharge 作者源码；显式修复 session/station 键错误；运行真正优化器与完整动作—响应循环，验证约束、能量与信息接口。关闭估计或未修复版本只用于诊断，不作为主要比较对象。控制器看不到环境的实际未来。
3. **预测的信息价值（value of predictive information）**：固定任务、动作、容量、服务目标及控制周期，比较修正反馈、同信息 MPC、恢复信息增强 MPC，并在可行时加入完全信息离线最优参照。固定控制器的 oracle 改善仅表示该控制器可以利用的收益，不是普遍信息价值上界。真正离线最优上界必须求解同一动作—响应系统，且验证可行性。

## 反事实与仿真

改变 pilot 后必须重新生成 actual current。不得在新动作下原样播放旧实际电流。若静态日志不能识别响应模型，则真实观测分析与假设下仿真分开；显式记录外生可充状态、需求、离开时间、功率响应及其假设。同一场景对所有策略使用相同外生状态与约束。容量不拥挤、快速反馈、恢复幅度很小可能本来就没有预测空间，负结果应保留。

## 数据与停止规则

原 128 会话是开发资料；涉及模型时按完整会话与时间划分，独立站点需单列。没有可靠请求/响应支持时，不声称真实场站因果收益。若合法离线信息上界与强基线几乎无差距，结论限定为本任务和设定；若固定控制器没有获益而离线最优仍有空间，先检查控制器能力。没有新机制时按应用核查报告，不预先命名新架构。
